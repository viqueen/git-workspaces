## Architecture

### Project Structure

This is a TypeScript CLI tool that provides Git workspace management utilities. The codebase is organized as follows:

- **src/bin/** - CLI entry points, one file per installed binary (see CLI Commands below)
- **src/lib/** - Core library functions, grouped by theme, each with an `index.ts` barrel re-exported from `src/lib/index.ts`:
  - `item/` - repository domain model (types, link parsing, location, filtering, status)
  - `config/` - configuration and CLI plumbing (read/write git workspace config, filtered registry queries, shared commander options)
  - `branches/` - git branch operations (list recent, exclude operational, select to checkout/delete)
  - `worktrees/` - git worktree operations (list, add, select to remove)
- **src/tasks/** - Task implementations run on the concurrent task pool (clone/sync an item, submit item tasks)
- **dist/** - Compiled JavaScript output (generated by TypeScript compiler)

Layering is one-directional: `bin → tasks → lib` and `bin → lib`. `lib` never imports from `tasks`.

### CLI Commands

Each binary is registered in `package.json` `bin` and invoked as a git subcommand (e.g. `git recent`).

**Branch commands** (operate on the current repo, no workspace config required):

- `git recent` - list recently checked-out branches, select one to check out
- `git merged` / `git squashed` - list merged/squashed branches, multi-select to delete
- `git stale` / `git tidy` - list branches, multi-select to delete
- `git list-remote` - list remote branches, select one to check out

**Worktree command** - `git work` with subcommands (operates on the current repo):

- `git work add <name>` - create a worktree under the `<item>-worktrees` sibling folder
- `git work remove` - list worktrees, multi-select to remove

**Workspace command** - `git workspace` with subcommands (backed by git config + registry):

- `git workspace` / `git workspace list` - list registered repos (default subcommand)
- `git workspace add <urlConnection>` - register a repo
- `git workspace remove` - remove matching repos
- `git workspace clone` / `git workspace sync` - clone/sync matching repos via the task pool
- `git workspace config` - interactively write the git global workspace config

`git work` and `git workspace` use [commander](https://github.com/tj/commander.js) subcommands in a single binary. The filter options (`-w/--workspace`, `--ns/--namespace`, `-h/--host`, `-s/--slug`, `-k/--keyword`) are shared via `withFilterOptions`. Workspace config is loaded lazily inside each action (not at startup) so `git workspace config` works before any config exists.

### Key Components

**Workspace Management**: The system uses git global config to store workspace configuration:

- `git.workspaces.root` - Root directory for all workspaces
- `git.workspaces.default` - Default workspace name
- Items are stored using @labset/leveldb-registry for persistence

**Item Model**: Core data structure representing a repository:

- `urlConnection` - Repository URL
- `workspace` - Workspace name
- `host`, `namespace`, `slug` - Parsed repository components

**External Dependencies**:

- `simple-git` - Git operations
- `inquirer` - Interactive CLI prompts
- `commander` - Command-line interface parsing
- `@labset/leveldb-registry` - Local database for workspace items
- `@labset/task-pool-executor` - Concurrent task execution

### Code Conventions

- TypeScript with strict mode enabled (`strictNullChecks`, `noImplicitAny`)
- CommonJS module system
- Apache-2.0 license headers required on all source files
- ESLint with custom rules including license notice validation
- Prettier formatting with 4-space tabs for TypeScript files
